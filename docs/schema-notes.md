# MC-001 — Proposal schema limits

The JSON Schema checks syntactic shape only. A valid proposal is not verified or accepted. The example uses deliberately fictitious pins; it must fail real preflight. Registry-level validation (unique logical IDs, cycle detection, dependency resolution, trusted policy lookup), path containment, digest verification, semantic compatibility, canonical serialization and receipt issuance are explicitly deferred. Source paths and entrypoints are data, never commands. SHA-256 fields are prefixed with sha256:; Git commit fields are full SHA-1 identifiers for the initial GitHub adapter. Future adapters may support additional revision types in a versioned schema. Policy and backend hashes must be checked against externally approved registries, not merely against proposal text. No acceptance state is available in the proposal schema.
